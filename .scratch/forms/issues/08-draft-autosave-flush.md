# 08: Draft, autosave with `lastEditedField`, and flush on blur/collapse/unmount

**What to build:** Editing an open form saves automatically. Typing pauses of 1500 ms trigger `SaveFormInst` with the full data and the JSON Pointer of the last edited field. Keyboard focus leaving the item body, collapsing the item, or unmounting it saves at once. The item header shows "Saving…", "Saved" (disappears after 2 s), or "Not saved" with a retry button. Saves happen regardless of validity. A save error shows inline only, no toast; a 400 refetches the list and the instance because the form is probably closed or deleted. A completed save updates the baseline; the field with keyboard focus keeps the user's value (merge rule applied to the save response, which the MSW fixture exercises through the computed `company.name`).

Delivers: `toJsonPointer` and `diffToJsonPointer` utilities, `mergeServerData` utility, store draft slice (`drafts` with `data`, `baseline`, `lastEditedPointer`, `saveStatus`, `errorMessage`, `showErrors`; setters; `dirtyInstanceIds`), `useSaveFormInst` mutation (`setQueryData` on success, list invalidation when status leaves `Open`), `useFormDraft` (debounce, in-flight coalescing with `pendingSave`, `flush()` returning the final status), the field focus tracker on the item body (`focusin` reads the closest `data-form-path`), save-status header UI, i18n `saving`, `saved`, `saveFailed`, `retry`. The save logic must be a plain function that takes the store and query client so ticket 10 can flush without a mounted composable.

Read spec sections 9.3 (`useSaveFormInst`), 10 (draft parts), 13.8 item 6, 13.9, 14.3, 14.4 (first three triggers), 14.5, 14.7, 16 in `.scratch/forms/spec.md`. This is the largest slice. Land the pure utilities with their unit tests first, then the store slice and mutation, then the composable and UI.
